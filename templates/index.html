3 How your request got here

  1. Cloudflare terminated TLS for kraken.rahulgpt.com and a tiny Worker forwarded the request to AWS.
  2. AWS Lambda started this process if none was warm. Kraken is a normal long running server, so Lambda runs it as is and pays nothing while idle.
  3. The Lambda Web Adapter turned the event back into plain HTTP and opened a TCP connection to 127.0.0.1:8000. That is the socket peer you see above.
  4. Kraken accept()ed it, queued it on the thread pool, read the bytes, parsed them, looked up / in the route table and ran the handler that rendered this page.

What's inside

  • Socketssocket, bind, listen and accept on a plain TCP port, with receive timeouts so idle clients can't pin a worker.
  • Thread poolConnections are queued and handled by 20 worker threads from owl, my C utility library.
  • HTTP/1.1 parserRequest line, headers, Content-Length bodies, url decoding and query strings. Malformed requests get a 400.
  • RoutingExpress style register_route(server, "/hello", handler) with O(1) hash map lookup.
  • Static filesMultiple static directories, index.html for folders, MIME types, chunked file reads and path traversal protection.
  • TemplatesSingle pass {{placeholder}} rendering from strings or files, the same thing that built this page.
